# Сборка и релизы Lumen RU

Все сборки выполняются локально на Ubuntu Server. GitHub хранит исходники, теги и готовые артефакты. GitHub Actions не используется. Репозиторий оригинала доступен только для чтения в рамках этого процесса.

## Идентификаторы и версии

- Репозиторий: `https://github.com/s0dom667-maker/Lumen-RU`.
- `origin`: `https://github.com/s0dom667-maker/Lumen-RU.git`.
- `upstream`: `https://github.com/subhashhhhhh/Lumen.git`. Его push URL намеренно заблокирован.
- Ветка выпуска: `main`. Общая история с Lumen сохранена, коммиты оригинальных авторов не переписаны.
- APK applicationId: `io.github.s0dom667maker.lumenru`; имя: **Lumen RU**.
- Namespace Kotlin остаётся `com.subhashh.lumen`, чтобы не переписывать архитектуру и импорты. Это не идентификатор установленного приложения.
- FileProvider использует `${applicationId}.files`, зависимости AndroidX — свои authority с `${applicationId}`. Фактические authority и пользовательское разрешение проверяются в собранном APK.
- Для RU зашифрованное хранилище находится в `.LumenRUVault`; данные официального `.LumenVault` не мигрируют автоматически. Обычная медиатека и скрытие через `.nomedia` относятся к общим файлам телефона.
- Наша версия задаётся только в `version.properties`. `versionName=X.Y.Z` соответствует Git-тегу `vX.Y.Z`. `versionCode` увеличивается на единицу при каждом новом релизе. Он не связан с versionCode оригинального Lumen.
- `upstream.properties` хранит версию, тег и полный коммит оригинала. Скрипт включает их в описание каждого релиза.
- `.github/lumen-ai.commit` закрепляет движок именно исходного релиза. `tools/release/lumen-ai-ru.patch` меняет только тексты уведомлений и добавляет ресурсы. Модели и алгоритмы не меняются.

## Требования

Установите Git, авторизованный `gh`, Python 3.10+, JDK 21, Android SDK command-line tools, `keytool`, GnuPG и Gitleaks. Используются версии SDK/NDK/CMake исходного проекта: Android 37.0, Build Tools 37.0.0, NDK 30.0.16248370, CMake 4.1.2. Gradle 9.8.2 загружается wrapper-скриптом. Нужен сетевой доступ к GitHub, Google Maven/SDK и Maven Central. Телефон и эмулятор для обычного выпуска не требуются.

Можно использовать уже установленный SDK. Укажите его через `ANDROID_HOME` или локальный `local.properties`:

```properties
sdk.dir=/absolute/path/to/Android/Sdk
```

На текущем сервере отдельные инструменты RU находятся в `.toolchains/`; SDK использует существующие платформы/Build Tools через ссылки, а NDK, CMake и тестовый образ установлены отдельно. Другие проекты не изменяются. JDK 21 в `.toolchains/jdk-21*` подхватывается автоматически, если `JAVA_HOME` не задан. Для другого расположения:

```bash
export JAVA_HOME=/absolute/path/to/jdk-21
export ANDROID_HOME=/absolute/path/to/Android/Sdk
"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" \
  'platforms;android-37.0' 'build-tools;37.0.0' \
  'ndk;30.0.16248370' 'cmake;4.1.2'
```

Gitleaks: установите официальный бинарный файл [из релизов](https://github.com/gitleaks/gitleaks/releases), проверив SHA-256 по опубликованному checksums-файлу. На этом сервере установлен Gitleaks 8.30.1 в `.toolchains/gitleaks/gitleaks`. Другой путь можно передать переменной `GITLEAKS`.

Настройте авторство Git локально в этом репозитории. `gh api user --jq .login` должен показывать `s0dom667-maker`. Git использует HTTPS и credential helper `gh`; токен в URL не нужен.

## Постоянная подпись

Ключ **уже создан**. Не генерируйте новый ключ для очередного релиза: иначе Android не установит обновление поверх прежней версии.

По умолчанию конфигурация находится **вне checkout**:

```text
../.android-release-private/lumen-ru/signing.properties
../.android-release-private/lumen-ru/lumen-ru-release.p12
```

Каталог имеет права `700`, файлы — `600`. Для другого пути задайте `LUMEN_RU_SIGNING_PROPERTIES`. Конфигурация имеет следующие поля; значения паролей здесь намеренно не приводятся:

```properties
storeFile=/absolute/path/outside/repository/lumen-ru-release.p12
storePassword=<пароль хранилища>
keyAlias=lumen-ru
keyPassword=<пароль ключа>
```

Это PKCS12 с RSA-4096. Публичный SHA-256 сертификата — в `signing-certificate.sha256`. Скрипт сравнивает с ним подпись каждого APK и не создаёт ключи автоматически. Прямой release build без конфигурации подписи завершается ошибкой. Пароли не передаются в командной строке, не записываются в исходники и не сохраняются pipeline-скриптом в Gradle configuration cache.

Если запускаете Gradle вручную, используйте `--no-configuration-cache`. Содержимое `.gradle/`, `.toolchains/`, `.deps/`, `local.properties`, ключи и `out/` исключены из Git. Перед публикацией дополнительно проверяются список файлов, точные байты действующего ключа/паролей и вся Git-история через Gitleaks.

## Локальная сборка

```bash
./release.sh --build-only
```

Команда не увеличивает версию, не создаёт коммитов/тегов и ничего не публикует. Она:

1. Получает закреплённый Lumen AI в `.deps/lumen-ai`, применяет проверяемый патч только уведомлений и останавливается при посторонних изменениях движка.
2. Проверяет полноту русского перевода, параметры форматирования и формы `one/few/many/other`, а также изменения английского оригинала.
3. Проверяет секреты в публикуемых файлах и полной локальной Git-истории.
4. Проверяет пять сценариев release-скрипта в одноразовых Git-репозиториях (patch, minor, откат при ошибке, отсутствие публикации при build-only, загрузка assets черновика по release ID до публикации), затем выполняет `:app:assembleRelease :app:testDebugUnitTest :app:lintRelease`.
5. Проверяет подпись v2, постоянный сертификат, applicationId, версии, название, authority провайдеров, разрешения, русские ресурсы, ABI и лицензии в APK.
6. Копирует **универсальный** APK, `SHA256SUMS.txt` и отчёт `BUILD.json` в `out/X.Y.Z/`.

Lint использует `app/lint-baseline-upstream.xml`: в нём 145 существовавших в Lumen 0.4.2 ошибок (проверены по исходникам тега). Новые ошибки и ошибки переводов не исключаются. Не пересоздавайте baseline, чтобы скрыть новые проблемы. Предупреждения исходного проекта сохраняются в отчёте.

Unit-тесты выполняются на debug-варианте, поскольку upstream создаёт тестовые задачи для него. Выпускной APK проверяется отдельно после R8 и подписи. Специальные Robolectric-тесты проверяют русские строки и числительные 1/2/5/21/22/25, FileProvider с нашим идентификатором и сравнение версий встроенным обновлятором. Это не заменяет проверку камеры, GPU/NPU и всех моделей на физических телефонах.

Пример ручной проверки артефакта:

```bash
python3 tools/release/verify-apk.py \
  out/1.0.0/Lumen-RU-1.0.0-universal.apk --sdk "$ANDROID_HOME"
(cd out/1.0.0 && sha256sum -c SHA256SUMS.txt)
```

Сначала русский язык выбирается по языку Android. На Android 13+ его можно выбрать отдельно в системных настройках приложения. Локализация интерфейса не меняет языки, поддерживаемые моделями OCR и субтитров.

## Выпуск исправления и функционального обновления

Сначала завершите изменения, переводы и их проверку, затем закоммитьте исходники в `main`:

```bash
./release.sh patch   # 1.0.0 → 1.0.1; versionCode + 1
./release.sh minor   # 1.0.1 → 1.1.0; versionCode + 1
```

Скрипт требует чистый checkout, правильные HTTPS fetch/push URL `origin`, правильный аккаунт GitHub и отсутствие новых удалённых коммитов, не включённых в локальную ветку. Параллельные запуски исключены файловой блокировкой.

После успешной сборки скрипт коммитит новую версию, создаёт аннотированный тег, отправляет только `main` и этот тег в `origin`, затем вызывает `gh release create` для черновика. После загрузки APK, SHA-256 и отчёта черновик становится стабильным релизом (`prerelease=false`, Latest). Obtainium увидит только готовый релиз. Версия оригинального Lumen и постоянный сертификат указаны в описании.

При ошибке сборки версия возвращается к прежней. Если уже создан коммит/тег или часть релиза загружена, продолжите **ту же версию**:

```bash
./release.sh --publish-current
```

Эта команда используется и для первоначального выпуска версии из `version.properties`. При повторной попытке используются прежние проверенные файлы `out/X.Y.Z/`, если тег и коммит совпадают; артефакты с другими контрольными суммами не заменяются. Не удаляйте этот каталог до завершения загрузки. Уже опубликованные релизы, assets и теги не перезаписываются. Force push и удаление релизов не используются.

## Обновление оригинального Lumen

Проверить версии оригинала:

```bash
gh release list --repo subhashhhhhh/Lumen
```

Начать слияние конкретного стабильного тега:

```bash
tools/release/update-upstream.sh v0.4.3
```

Скрипт выполняет fetch **только из upstream** и создаёт ветку `upstream-update/v0.4.3`. Теги оригинала помещаются в `refs/remotes/upstream/tags/`, чтобы не конфликтовать с нашими `vX.Y.Z`. Затем выполняется обычный merge с сохранением авторства и истории, без автоматического завершения.

При конфликтах вручную объедините обе стороны. Сохраните наш applicationId, подпись, версионирование, русские ресурсы, отдельное хранилище, адрес обновлений и локальную сборку. Не применяйте `checkout --theirs`, `reset --hard` или копирование всего upstream поверх RU. Если upstream вернул `.github/workflows`, удалите их в ветке обновления до сборки.

После изменения `.github/lumen-ai.commit` helper останавливается: он не затирает существующий engine checkout. Переместите `.deps/lumen-ai` в резервный каталог **вне checkout**, запустите `tools/release/prepare-deps.sh` для нового pin. Если текстовые уведомления upstream изменились, адаптируйте только `tools/release/lumen-ai-ru.patch`; не меняйте каталоги моделей, веса и настройки распознавания. Проверяйте лицензии и новые зависимости upstream.

Проверка покажет новые строки, удалённые ключи и английские тексты, требующие повторного просмотра. Добавьте переводы в `app/src/main/res/values-ru/strings.xml`; для русских plurals нужны четыре формы. Обновите патч уведомлений, если требуется. После перевода и смысловой проверки запишите новый снимок английских ресурсов:

```bash
python3 tools/release/check-translations.py --record-source
python3 tools/release/check-translations.py
```

Не используйте `--record-source` как способ пропустить перевод: сначала просмотрите изменение оригинала. Снимок сохраняет английские тексты, поэтому их изменения видны в diff.

Завершить проверку и merge-коммит:

```bash
tools/release/update-upstream.sh --finish v0.4.3
```

Скрипт обновит `upstream.properties`, проверит переводы, подпись, секреты, сборку, тесты и APK. При необходимости добавьте новые файлы явно через `git add`. Просмотрите diff, затем объедините ветку в `main` **без squash**. Выпускайте `patch` или `minor`. Обновление upstream само по себе ничего не отправляет и не публикует. Отказаться от незавершённого merge можно через `git merge --abort`.

## Резервная копия ключа

Создать и проверить зашифрованную копию:

```bash
python3 tools/release/backup-signing.py
```

Скрипт сохраняет PKCS12, `signing.properties` и отпечаток сертификата в AES-256 GPG-архиве, проверяет расшифровку в памяти и записывает SHA-256. Архивы находятся в `../.android-release-private/backups/lumen-ru/`, отдельный файл восстановления — в `../.android-release-private/lumen-ru-backup-recovery.txt`. Секреты не печатаются.

**Скопируйте архив и файл восстановления в разные защищённые места вне сервера** (например, зашифрованный носитель и менеджер паролей). Локальная копия на том же диске не защищает от потери сервера. Не публикуйте их в GitHub Releases, Issues или репозитории.

Восстановление на другом сервере:

```bash
umask 077
mkdir -p /secure/lumen-ru-restored
gpg --decrypt /secure/backup.tar.gpg | tar -x -C /secure/lumen-ru-restored
```

Введите пароль из файла восстановления локально в GnuPG. Измените только `storeFile` на новый абсолютный путь, сохраните прежние ключ, alias и пароли; установите права `700` на каталог и `600` на файлы. Задайте `LUMEN_RU_SIGNING_PROPERTIES` и выполните `./release.sh --build-only`. Проверка сертификата должна совпасть с `signing-certificate.sha256`. Потеря ключа не исправляется генерацией нового: продолжить совместимые обновления без прежнего ключа нельзя.
